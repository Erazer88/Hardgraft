B. CONTRAINTE TECHNIQUE
PRINCIPALE
Projet développé par :

   ●​ 1 humain non spécialiste du code ;
   ●​ Codex / agents IA.

Donc :

LA LISIBILITÉ DU CODE EST UNE FONCTIONNALITÉ.

Interdictions :

    ●​    gros système monolithique supplémentaire dans app.js ;
    ●​    logique gameplay mélangée au rendu Canvas ;
    ●​    valeurs d'équilibrage dispersées ;
    ●​    comportements implicites impossibles à tester ;
    ●​    « vraie IA » générative pour gérer les colonies ;
    ●​    framework ajouté sans justification majeure.

Préférer :

    ●​    JavaScript simple ;
    ●​    modules clairement séparés ;
    ●​    configuration data-driven ;
    ●​    fonctions déterministes ;
    ●​    tests unitaires.

D. RÈGLES DE SIMULATION
Le rendu ne doit jamais être la source de vérité.

Séparer :

simulation de animation visuelle.

La simulation doit pouvoir être testée sans Canvas.

Les recettes, coûts et technologies doivent être déclaratifs.

Exemple conceptuel :

{
    id: "iron_plate",
    inputs: [{ resource: "iron_ore", amount: 2 }],
    outputs: [{ resource: "iron_standard", amount: 1 }],
    duration: 4
}


Les valeurs exactes sont provisoires.

Ne pas considérer les nombres temporaires comme définitifs.

H. AGENT 02 — SIMULATION /
RESSOURCES / CONSTRUCTION
Dépendance
Agent 00 terminé.

Peut travailler parallèlement à Agent 01 si les fichiers sont séparés.


Mission
Créer le noyau économique minimal.


Ressources initiales
IDs stables recommandés :

   ●​   iron ;
   ●​   copper ;
   ●​   silicon ;
   ●​   carbon ;
   ●​   water.

Prévoir immédiatement la possibilité d'ajouter :

   ●​ intermédiaires ;
   ●​ déchets ;
   ●​ ressources inconnues.


Construction
Un bâtiment possède :

   ●​   coût ;
   ●​   durée ;
   ●​   état de construction ;
   ●​   production éventuelle ;
   ●​   consommation énergétique éventuelle.

Durée initiale cible : environ 3–4 secondes.


Démolition

Prévoir un remboursement configurable.

Valeur V0 : 100 %.


Important

Aucun coût gameplay ne doit être enfoui dans le rendu.


Definition of Done
Pouvoir :

   ●​   disposer d'un inventaire ;
   ●​   consommer des matériaux ;
   ●​   lancer une construction ;
   ●​   voir son timer ;
   ●​   terminer la construction ;
   ●​   démolir ;
   ●​   récupérer les ressources.

Tests unitaires sans Canvas obligatoires.




I. AGENT 03 — USINE ET BLOCS
Dépendances
Agents 00 + 02.


Mission
Créer le premier véritable cœur de gameplay.


Usine
Une usine :

   ●​   est placée physiquement sur la planète ;
   ●​   possède un niveau/rang ;
   ●​   possède une surface interne finie ;
   ●​   possède une consommation énergétique globale.

L'intérieur de l'usine est un canvas/espace séparé contenant des blocs flottants.


Bloc
Chaque bloc peut posséder :

   ●​   ports entrée ;
   ●​   ports sortie ;
   ●​   stock interne ;
   ●​   capacité ;
   ●​   recette ;
   ●​   durée de cycle.


Transferts
Quand une production termine :

si le prochain bloc a de la place : → transfert immédiat.

Sinon : → le stock reste bloqué.


Placement
Le placement n'a aucun impact sur :

   ●​ vitesse ;
   ●​ rendement ;
   ●​ énergie.

Impact uniquement :

   ●​ lisibilité ;
   ●​ place disponible.


Blocs V0
Implémenter seulement :

   ●​   entrée ;
   ●​   sortie ;
   ●​   transformation ;
   ●​   stockage ;
   ●​   division ;
   ●​   fusion.

Préparer l'architecture pour :

    ●​   filtre ;
    ●​   règle ;
    ●​   assemblage ;
    ●​   séparation ;
    ●​   data.


UX
Priorité mobile :

    ●​   drag ;
    ●​   sélection ;
    ●​   création connexion ;
    ●​   suppression ;
    ●​   déplacement ;
    ●​   zoom/pan si nécessaire.


Definition of Done
Une petite chaîne doit pouvoir réellement tourner en boucle sans UI debug.

Exemple :

Entrée minerai​
→ transformation​
→ stockage​
→ sortie.

Les stocks doivent pouvoir créer un vrai goulot d'étranglement.




J. AGENT 04 — ÉNERGIE PLANÉTAIRE
Dépendance
Agent 02.


Mission
Créer un système d'énergie simple.


Règle

Pas de câbles bloc par bloc.

Une usine consomme une puissance totale.

Une planète possède :

   ●​ production disponible ;
   ●​ consommation.

Si production insuffisante : appliquer une règle simple de ralentissement ou d'insuffisance.

Les chiffres doivent être facilement ajustables.


V0
Une seule ou deux sources énergétiques suffisent.

Ne PAS coder :

   ●​ batteries interplanétaires ;
   ●​ Dyson ;
   ●​ système énergétique avancé.

Préparer seulement les interfaces futures.




K. AGENT 05 — ROUTES ET HUB
PLANÉTAIRE
Dépendances
Agents 00 + 02.


Mission
Créer la logistique hors usine.


Règle
Dans une usine : transfert instantané.

Sur la planète : transport avec durée.

V0
Créer :

   ●​     hub central ;
   ●​     connexion installation → hub ;
   ●​     route terrestre simple ;
   ●​     petits véhicules animés ;
   ●​     capacité/débit simplifié.

Pas de microgestion individuelle des véhicules.

L'objectif premier est : voir vivre le réseau.

Les routes doivent être visuellement agréables sur le terrain.

Ne pas transformer immédiatement le terrain en puzzle de pathfinding complexe.




L. AGENT 06 — RECHERCHE ET
TECHNOLOGIE
Dépendances
Simulation de base fonctionnelle.


Mission
Créer le moteur de technologies sans arbre entièrement révélé.


Principe
Les technologies principales sont fixes.

Mais elles apparaissent progressivement selon des triggers.

Exemples :

construction centre déchets
→ révéler recyclage
→ révéler séparation avancée

Une technologie possède :

   ●​   conditions de révélation ;
   ●​   coût de calcul ;
   ●​   durée ;
   ●​   prérequis connus ;
   ●​   effets.


Interface
Montrer :

   ●​ technologies actuellement connues ;
   ●​ pistes accessibles ;
   ●​ silhouettes/brouillard éventuel du reste.

Ne PAS montrer tout l'arbre complet.


Anti-RNG
Les technologies essentielles ne doivent jamais dépendre uniquement d'une découverte
aléatoire.




M. AGENT 07 — EXPLORATION
Mission
Faire de la connaissance progressive une vraie mécanique.


États d'information
Pour un monde :

   1.​ non observé ;
   2.​ télescope ;
   3.​ sonde ;
   4.​ visite physique.

Chaque état révèle davantage de propriétés.

Ne jamais révéler immédiatement toutes les ressources d'une planète éloignée.

Événements d'exploration
Prévoir un système générique capable de signaler :

    ●​    anomalie ;
    ●​    signal ;
    ●​    épave ;
    ●​    ressource ;
    ●​    phénomène.

L'événement doit proposer de la curiosité sans devenir une quête classique.




N. AGENT 08 — DATA
Dépendances
Usines + technologies fonctionnelles.


Mission
Créer uniquement une première vertical slice du réseau data.


V0
Ajouter :

    ●​    datacenter ;
    ●​    émetteur/récepteur dans une usine ;
    ●​    connexion data ;
    ●​    bloc Analyse qualité.

Exemple :

Datacenter​
→ Récepteur usine​
→ Analyse qualité​
→ bloc de fabrication.

Effet :

production normalement : Fer standard

avec analyse : Fer avancé

Fer avancé peut remplacer Fer standard dans les recettes.

Certaines recettes futures pourront exiger explicitement Fer avancé.


Important
Ne PAS encore ajouter :

    ●​   virus ;
    ●​   paquets ;
    ●​   corruption complexe ;
    ●​   cybersécurité ;
    ●​   internet galactique complet.

Mais concevoir la data comme un véritable type de flux pour pouvoir les ajouter.




O. AGENT 09 — POPULATION / VIE
VISUELLE
Dépendances
Planète et industrie fonctionnelles.


Mission
Ajouter une présence humaine abstraite sans créer un city-builder.


Population
Calcul simplifié à partir de :

    ●​ âge de la colonie ;
    ●​ habitabilité ;
    ●​ puissance industrielle.

Pas de :

    ●​ logement détaillé ;
    ●​ nourriture détaillée ;
    ●​ citoyens individuels.

Visuel
Faire apparaître progressivement :

   ●​   petites zones habitées ;
   ●​   éclairage ;
   ●​   routes secondaires décoratives ;
   ●​   activité ;
   ●​   constructions civiles.

Placement naturellement privilégié :

   ●​   plaines ;
   ●​   côtes ;
   ●​   rivières ;
   ●​   zones crédibles.

La population doit surtout donner la sensation :

la vie est en train d'apparaître.




P. AGENT 10 — ARCHE / LORE MINIMAL
Mission
Ne PAS écrire tout le scénario.

Créer seulement le support technique.

L'Arche doit rester accessible comme :

   ●​ lieu d'origine ;
   ●​ hub de connaissance ;
   ●​ futur centre du Contexte.

Prévoir une structure pour :

   ●​   fragments d'archives ;
   ●​   découvertes ;
   ●​   corrélations ;
   ●​   textes ;
   ●​   événements narratifs.

Les textes doivent être séparés du code.

Ne pas construire de vérité définitive sur l'origine de l'Arche.

MAINTENANT
Interdit pour la première phase :

   ●​   IA autonome concevant librement des colonies ;
   ●​   doctrines galactiques complètes ;
   ●​   rebellions complexes ;
   ●​   guerres ;
   ●​   civilisations intelligentes complètes ;
   ●​   extermination ;
   ●​   politique galactique ;
   ●​   Contexte complet ;
   ●​   batteries interstellaires ;
   ●​   Dyson ;
   ●​   trajectoires orbitales avancées ;
   ●​   économie monétaire ;
   ●​   marché ;
   ●​   milliers d'artefacts ;
   ●​   virus/data complexe ;
   ●​   simulation détaillée de centaines de systèmes actifs.

Ces mécaniques font partie de la direction future.

Elles ne doivent pas parasiter la première boucle jouable.




R. PREMIER OBJECTIF JOUABLE
Avant toute extension complexe, Hardgraft doit permettre ceci :

   1.​ ouvrir une partie ;
   2.​ voir l'Arche ;
   3.​ observer plusieurs mondes ;
   4.​ sélectionner une planète ;
   5.​ commencer avec quelques ressources/robots ;
   6.​ construire une énergie ;
   7.​ extraire fer/cuivre/etc. ;
   8.​ poser une usine ;

   9.​ ouvrir l'usine ;
   10.​créer une chaîne de blocs ;
   11.​voir réellement les stocks circuler ;
   12.​produire un composant utile ;
   13.​construire de nouvelles installations ;
   14.​voir des routes et véhicules ;
   15.​améliorer progressivement la planète ;
   16.​recevoir une première piste technologique ;
   17.​lancer une sonde ;
   18.​découvrir quelque chose donnant envie de continuer.

Si ces 18 étapes ne sont pas satisfaisantes :

NE PAS PASSER À L'AUTOMATISATION GALACTIQUE.
